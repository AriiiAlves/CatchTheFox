Uma [ROP chain](./index.mdx) precisa de espaço: cada gadget e cada argumento ocupa 8 bytes depois do endereço de retorno. Quando o overflow só alcança o `rbp` salvo e o endereço de retorno (ou pouco mais), a chain não cabe.

Stack Pivoting resolve isso **movendo o `rsp` para outra região que controlamos**, onde a chain completa já está escrita. Como `ret` é `pop rip` e `pop` lê de `rsp`, a partir do momento em que `rsp` aponta para a nossa região, os próximos `ret` consomem a chain de lá.

O pivot não contorna nenhuma proteção por si só: continua sendo ROP (por causa do NX) e continua precisando de endereços conhecidos (por causa de PIE/ASLR). Ele resolve só a falta de espaço.

## Onde colocar a chain

A região precisa ter **endereço conhecido** e ser **gravável por nós**:

| Região | Quando serve |
|---|---|
| `.bss` / `.data` | Sem PIE (endereço fixo), ou com a base vazada. Preencha com um input em variável global ou com um `read(0, bss, n)` |
| O próprio buffer na stack | Buffer grande, mas overflow curto. Requer leak da stack |
| Heap | O programa guarda input na heap e o endereço foi vazado |

Ao usar a `.bss`, aponte para o meio dela (`elf.bss() + 0x800`, por exemplo). As funções chamadas pela chain usam a stack para baixo do `rsp`, e logo abaixo da `.bss` ficam a GOT e páginas somente leitura.

## Pivot com `leave; ret`

É o mais comum, por dois motivos: toda função que termina em `leave; ret` já é o gadget, e o `rbp` salvo fica logo antes do endereço de retorno, então o overflow o sobrescreve de qualquer jeito.

`leave` equivale a `mov rsp, rbp; pop rbp`. Quem controla `rbp` controla `rsp` no `leave` seguinte:

| Passo | Instrução | Efeito |
|---|---|---|
| 1 | `leave` da função vulnerável | `rbp = &nova_stack` (o `pop rbp` pega o nosso valor) |
| 2 | `ret` da função vulnerável | Pula para o gadget `leave; ret` |
| 3 | `leave` do gadget | `rsp = rbp = &nova_stack`; o `pop rbp` consome os 8 primeiros bytes |
| 4 | `ret` do gadget | `rip = [nova_stack + 8]`: primeiro gadget da chain |

```py
leave_ret = rop.find_gadget(['leave', 'ret'])[0]
nova_stack = elf.bss() + 0x800

# 1ª etapa: escrever a chain em nova_stack (aqui, supondo que o programa leia para lá)
chain = p64(0)                          # vira rbp
chain += p64(pop_rdi) + p64(elf.got['puts']) + p64(elf.plt['puts']) + p64(elf.sym['main'])
p.send(chain)

# 2ª etapa: overflow curto, só rbp salvo e return address
p.send(b'A' * offset_ate_rbp + p64(nova_stack) + p64(leave_ret))
```

Em 32 bits é idêntico, com `ebp`/`esp` e 4 bytes.

Quando a chain está no próprio buffer da stack e o endereço dele é conhecido, o mesmo truque funciona com `rbp salvo = &buffer`: o overflow de 16 bytes pivota para o início do input.

## Outros gadgets de pivot

```nasm
pop rsp ; ret                 ; o valor seguinte da stack vira rsp
xchg rsp, rax ; ret           ; quando rax aponta para dados controlados (retorno de read/malloc)
mov rsp, rbx ; ret
add rsp, 0x100 ; ret          ; a chain está mais adiante na mesma stack
sub rsp, 0x100 ; ret          ; a chain está antes (no buffer)
push rax ; pop rsp ; ret
```

Para os que usam um registrador, coloque antes o gadget que o carrega:

```py
payload = b'A' * offset + p64(pop_rax) + p64(nova_stack) + p64(xchg_rsp_rax)
```

O pwntools gera o pivot com `rop.migrate(endereco)`, escolhendo um desses gadgets.

## Off-by-one no `rbp`

Uma variação: um overflow de **um byte** que só atinge o byte baixo do `rbp` salvo. Esse `rbp` corrompido vira `rsp` no `leave` da função **chamadora**, deslocando a stack dela para dentro de uma região que controlamos (muitas vezes o próprio buffer, que está logo abaixo). É um pivot "de graça", sem tocar no endereço de retorno.
