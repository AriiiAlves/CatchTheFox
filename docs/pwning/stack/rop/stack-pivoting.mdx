Às vezes não temos espaço suficiente na stack para colocar os gadgets ROP (stack limitada), ou a stack original está protegida.

A solução para isso é o stack pivoting: Vamos criar uma nova stack para usarmos os gadgets. Ou seja, mudamos para um lugar maior e mais livre onde temos mais espaço para trabalhar.

1. Alocamos memória em outro lugar (heap, .data, etc.). Precisamos `obter o endereço de uma região de memória controlável`.
2. Encadeamos os gadgets na nova stack ([Gadget 1] → [Gadget 2] → [Gadget 3] → ...)
3. Usamos um gadget que muda o registrador RSP para nossa nova stack (`mov rsp, rax` + `ret`) (stack pivoting!)
4. A CPU agora usa nossa nova stack. 

Lembre-se que o `ret` é uma instrução compacta que na verdade executa `pop rip`. E lembre-se que `pop` usa `rsp` como referência para fazer o "pop" de um elemento da stack. Assim, o `pop rip` pega o endereço para o qual `rsp` aponta e coloca no `rip`. Portanto, se fizermos `rsp` apontar para a nossa região de memória, o próximo `ret` continua a chain a partir de lá.

O Stack Pivoting não contorna nenhuma proteção por si só (continua precisando de um leak se houver PIE/ASLR, e a chain continua sendo ROP por causa do NX). O que ele resolve é a **falta de espaço**: quando o overflow só permite sobrescrever o `return address` e mais um ou dois valores, movemos a stack para um lugar onde cabe a chain inteira.

Resumindo: **Stack Pivoting = Redirecionar RSP/ESP para região controlada + ROP chain pré-montada**.

## Encontrando a nova stack

1. Heap (via malloc/free)
2. Seção .data ou .bss
3. Stack secundária (usando vazamento de endereço)
4. Memória mapeada (mmap)

## Gadgets comuns para pivoting

```nasm
# 1. Movimento direto
mov rsp, rax ; ret        # Copia RAX para RSP
xchg rsp, rax ; ret       # Troca RSP com RAX

# 2. Aritmético (quando a chain está um pouco mais adiante na própria stack)
add rsp, 0x100 ; ret      # Pula 0x100 bytes para frente
sub rsp, 0x100 ; ret      # Volta 0x100 bytes

# 3. Indireto
push rax ; pop rsp ; ret  # Move RAX para RSP via push/pop

# 4. O mais comum de todos: leave ; ret
leave ; ret               # mov rsp, rbp ; pop rbp ; ret
```

Para o stack pivoting com `rax` funcionar, precisamos de um gadget `pop_rax` para colocar o endereço desejado em `rax`.

```nasm
[Buffer overflow...]
[pop_rax_gadget]     ← RIP vai aqui primeiro (return address)
[&nova_stack]        # Valor para RAX
[mov_rsp_rax_gadget] # Gadget que faz pivot
```

## Pivot com `leave ; ret`

Esse é o caso mais frequente em CTFs, porque **toda função que termina com `leave; ret` já é um gadget de pivot**, e porque o `RBP` salvo fica logo antes do `return address`, ou seja, o Buffer Overflow já o sobrescreve de graça.

O `leave` faz `mov rsp, rbp ; pop rbp`. Então, se controlamos o `RBP` salvo, controlamos o `RSP` depois do próximo `leave`:

```
Stack após o overflow:
[buffer...]
[RBP salvo]      = &nova_stack          ← controlamos
[return address] = endereço de "leave ; ret"

Execução:
1. leave da função vulnerável: rbp = &nova_stack (pop rbp pega o nosso valor)
2. ret: pula para o gadget leave ; ret
3. leave do gadget: rsp = rbp = &nova_stack ; pop rbp (consome os 8 primeiros bytes da nova stack)
4. ret: pop rip = segundo valor da nova stack → nossa chain começa aqui!
```

Por isso a nova stack costuma começar com 8 bytes de lixo (que viram o `rbp`) seguidos da chain. Isso é exatamente o que o pwntools faz em `rop.chain()` quando pedimos um `rop.migrate(addr)`.

Em 32 bits, é a mesma coisa com `ebp`/`esp` e 4 bytes.

## Onde colocar a chain

A nova stack precisa estar em um endereço que conhecemos e onde conseguimos escrever:

- **`.bss`/`.data`** (sem PIE): o endereço é fixo. Um `read(0, bss, 0x200)` feito com um pequeno ROP inicial (ou um `gets` sobre uma variável global) escreve a chain lá, e aí pivotamos
- **Heap**: se o programa guarda nosso input na heap e vazou (ou podemos deduzir) o endereço
- **A própria stack**: se o buffer é grande o suficiente mas está *antes* do `return address`, o pivot pode apontar `rsp` de volta para o início do buffer (precisa de um leak da stack ou de um gadget `sub rsp, N ; ret`)
