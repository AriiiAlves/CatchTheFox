Com PIE/ASLR não sabemos os endereços absolutos, mas a stack (e a heap, e a GOT) já está cheia de ponteiros válidos. Em vez de escrever um endereço inteiro, o Partial Overwrite **altera só os bytes menos significativos de um ponteiro que já existe**, fazendo-o apontar para outro lugar próximo, na mesma região. Nenhum leak é necessário.

## Por que funciona

O ASLR randomiza a base de cada região em múltiplos de uma página (`0x1000`). Logo, os **12 bits baixos** (3 dígitos hexadecimais) de qualquer endereço são fixos: dependem só do offset dentro do arquivo. Os bits mais altos também são previsíveis (em x86-64, um binário PIE cai sempre em `0x55…`/`0x56…`), mas isso não ajuda: o overflow escreve a partir do byte baixo, e para chegar aos bytes altos teria que passar por cima dos aleatórios.

Como a memória é little endian, um overflow atinge primeiro o byte **menos** significativo do ponteiro. Parando de escrever no meio dele, os bytes altos (os aleatórios) ficam intactos.

| Bytes sobrescritos | Bits desconhecidos | Chance de acerto |
|---|---|---|
| 1 | 0 | 100%, desde que o alvo esteja na mesma faixa de `0x100` bytes |
| 2 | 4 (um dígito hex) | 1 em 16 |
| 3 | 12 | 1 em 4096 |

Uma chance em 16 é aceitável em CTF: basta rodar o exploit em laço.

## Exemplo

Binário com PIE. O endereço de retorno da função vulnerável aponta para `main+0x5a`, que termina em `...1da`. A função `win` fica em `...1f6`, na mesma página. Trocamos só o último byte:

```py
payload  = b'A' * offset     # padding até o return address
payload += b'\xf6'           # 0x...1da → 0x...1f6. Os outros 7 bytes não são tocados
p.send(payload)              # send, não sendline: o \n seria escrito no byte seguinte
```

Se `win` estivesse em outra página (`...2f6`), seriam 2 bytes, com um dígito no chute:

```py
for nibble in range(16):                    # tenta os 16 valores possíveis do dígito aleatório
    guess = (nibble << 12) | 0x2f6          # 0x02f6, 0x12f6, ..., 0xf2f6
    p = process('./vuln')
    p.send(b'A' * offset + p16(guess))
    try:
        p.sendline(b'echo ok')
        if b'ok' in p.recvuntil(b'ok', timeout=1):
            p.interactive()
            break
    except EOFError:
        pass
    p.close()
```

Se o alvo for um servidor que faz `fork` sem re-executar (o layout é o mesmo em toda conexão), um dos 16 chutes acerta com certeza. Se cada `process` re-randomiza o PIE, o laço acima ainda funciona, mas vale embrulhá-lo num `while True`: cada tentativa tem 1/16 de chance independente das anteriores.

## Requisitos e limitações

- **A leitura não pode acrescentar bytes**. `read` grava exatamente o que você envia. `gets`, `fgets` e `scanf("%s")` gravam um `\0` depois do input, e `strcpy` também: esse `\0` cai no byte seguinte do ponteiro. Às vezes isso é aproveitável (o byte nulo vira parte do endereço), mas normalmente estraga.
- **O alvo precisa estar na mesma região** do ponteiro original. Um return address que aponta para o binário só alcança o binário; para alcançar a libc, parta de um ponteiro da libc (o retorno da `main` para `__libc_start_call_main`, por exemplo, permite alcançar um *one_gadget* próximo).
- Em 64 bits, só um endereço pode ser parcialmente sobrescrito por overflow: tudo antes dele é reescrito por inteiro. Por isso o uso típico é "um salto só".

## Outros usos

- **Heap**: trocar o byte baixo de um `fd` para apontar para outro chunk próximo, sem leak da heap (em glibc ≥ 2.32, o [Safe Linking](../../heap/safe-linking.mdx) atrapalha).
- **GOT**: trocar os bytes baixos de uma entrada já resolvida para outra função próxima na libc.
- **Leak**: sobrescrever o byte baixo de um ponteiro que o programa imprime depois, fazendo-o apontar para um dado mais interessante.
