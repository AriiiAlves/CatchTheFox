`unlink` é a operação que remove um chunk de uma lista duplamente encadeada (unsorted, small ou large bin). Ela é executada quando um chunk livre é fundido com um vizinho durante o `free`, e quando o `malloc` retira um chunk de uma dessas bins.

```c
#define unlink(P, BK, FD) {
    FD = P->fd;
    BK = P->bk;
    FD->bk = BK;
    BK->fd = FD;
}
```

O interesse para exploração: são **duas escritas em memória cujos endereços e valores saem do próprio chunk**. Em 64 bits, `fd` fica no offset `0x10` e `bk` no offset `0x18`, então:

```c
FD->bk = BK;     // *(P->fd + 0x18) = P->bk
BK->fd = FD;     // *(P->bk + 0x10) = P->fd
```

Quem controla `fd` e `bk` de um chunk que vai sofrer `unlink` controla o que é escrito e onde.

## Unlink clássico (glibc < 2.3.4)

Sem nenhuma verificação, bastava:

```c
P->fd = alvo - 0x18;
P->bk = valor;
// unlink(P):  *alvo = valor        (e também *(valor + 0x10) = alvo - 0x18)
```

Uma escrita arbitrária, com a única condição de que `valor + 0x10` fosse gravável. Tem valor histórico: não funciona em nenhuma glibc atual.

## Proteção safe-unlinking (glibc 2.3.4+)

Desde 2004, a glibc confere se os vizinhos apontam de volta para o chunk antes de removê-lo:

```c
if (__builtin_expect (FD->bk != P || BK->fd != P, 0))
    malloc_printerr ("corrupted double-linked list");
```

Versões mais novas também conferem se o `size` do chunk bate com o `prev_size` do chunk seguinte (`corrupted size vs. prev_size`).

Isso elimina a escrita em endereço arbitrário, mas não o ataque: basta que exista, em um **endereço conhecido**, um ponteiro para `P`.

## Unsafe unlink

Cenário típico: um array global de ponteiros para chunks (`notes[]`), sem PIE ou com a base do binário vazada, e um heap overflow de um chunk para o seguinte.

Seja `ptr = &notes[0]`, e `notes[0]` apontando para os dados do chunk `A`. Dentro de `A`, forjamos um chunk falso `P` que começa exatamente no endereço que `notes[0]` guarda, com:

```c
P->fd = ptr - 0x18;
P->bk = ptr - 0x10;
```

A verificação passa, porque as duas contas caem em `*ptr`, que vale `P`:

- `FD->bk` = `*(ptr - 0x18 + 0x18)` = `*ptr` = `P` ✓
- `BK->fd` = `*(ptr - 0x10 + 0x10)` = `*ptr` = `P` ✓

Com o overflow, corrompemos o header do chunk seguinte (`B`) para o `free(B)` acreditar que o chunk anterior é `P` e está livre:

Ao executar `free(B)`:

1. O bit `P` de `B` é 0, então a glibc funde para trás: o chunk anterior começa em `B - prev_size` = `P`.
2. `unlink(P)` é chamado. As verificações passam.
3. As escritas acontecem: `*ptr = ptr - 0x10` e depois `*ptr = ptr - 0x18`.

Resultado: **`notes[0] = &notes[0] - 0x18`**. O ponteiro da nota passa a apontar para a região logo antes do próprio array.

Editando a nota 0, escrevemos `0x18` bytes de padding e, em seguida, novos valores para `notes[0]`, `notes[1]`... A partir daí, cada nota é uma leitura/escrita em endereço arbitrário, quantas vezes quisermos.

## Requisitos

- Um ponteiro para o chunk em **endereço conhecido** (array global sem PIE, ou base do binário/heap vazada).
- Um overflow (mesmo de poucos bytes) que alcance `prev_size` e o bit `P` do chunk seguinte. Um [off-by-one nulo](./heap-overflow.mdx#o-que-mais-dá-para-sobrescrever) basta para zerar o bit `P` quando o `size` do vizinho tem o byte baixo `0x01` (ex: `0x101` vira `0x100`).
- O `free` do chunk seguinte precisa **consolidar**: ele não pode ir para o tcache nem para a fastbin. Use chunks maiores que `0x410`, ou encha o tcache daquele tamanho antes (em glibc < 2.26, basta ser maior que `0x80`).
- O `size` do chunk falso precisa ser igual ao `prev_size` gravado em `B`.

A técnica continua funcionando nas glibc atuais. Implementação de referência: [`unsafe_unlink.c`](https://github.com/shellphish/how2heap) no how2heap.
