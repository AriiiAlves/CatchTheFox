Double Free é liberar o mesmo chunk duas vezes. O chunk entra **duas vezes na mesma lista**. Ao alocar uma das cópias, ficamos com um chunk que está **alocado e livre ao mesmo tempo**: o que escrevemos nos dados dele é lido pelo alocador como o ponteiro `fd`. O resultado é um `malloc` que devolve um endereço arbitrário.

O ataque descrito aqui é o clássico na fastbin (*fastbin dup*). No tcache a ideia é a mesma: veja [Tcache](./tcache.mdx).

## O ataque

`fd` de um chunk livre e os primeiros 8 bytes de dados de um chunk alocado são **a mesma posição de memória**.

A fastbin impede liberar duas vezes seguidas o chunk que está na cabeça da lista (veja [fasttop](#fasttop-double-free-check)), então libera-se outro chunk no meio:

```c
char *a = malloc(0x50);
char *b = malloc(0x50);

free(a);
free(b);
free(a);                     // double free: a está duas vezes na lista

char *x = malloc(0x50);      // devolve a (que continua na lista)
*(long *)x = alvo;           // escrito como dado, lido como fd
malloc(0x50);                // devolve b
malloc(0x50);                // devolve a de novo
char *evil = malloc(0x50);   // devolve alvo + 0x10
```

Na fastbin, o `fd` aponta para o **header** do chunk. Para o `malloc` devolver o endereço `T`, o `fd` escrito deve ser `T - 0x10`.

## Passo a Passo

1. Ache o double free: um `delete` que não zera o ponteiro e pode ser chamado duas vezes no mesmo índice.
2. Garanta que os chunks caem na bin desejada. Em glibc ≥ 2.26, encha o tcache daquele tamanho primeiro (7 chunks liberados) para os seguintes irem à fastbin. Atenção na hora de alocar de volta: quando o `malloc` tira um chunk da fastbin, ele move os restantes para o tcache, o que muda a ordem das devoluções. Os exemplos `fastbin_dup*` do [how2heap](https://github.com/shellphish/how2heap) mostram a sequência exata para cada versão (em geral usando `calloc`).
3. `free(a)`, `free(b)`, `free(a)`.
4. Aloque do mesmo tamanho e escreva o endereço alvo nos primeiros 8 bytes.
5. Aloque mais duas vezes (saem `b` e `a`).
6. A alocação seguinte devolve o alvo. Escrever nela é escrever no alvo.

## Proteções

### Fasttop (Double Free check)

Ao liberar para a fastbin, o `free` confere só se o chunk é o mesmo que já está na cabeça da lista. Se for, aborta com `double free or corruption (fasttop)`. Não olha o resto da lista, por isso `free(a); free(b); free(a);` passa.

### Size Check (malloc)

Ao tirar um chunk da fastbin, o `malloc` confere se o `size` dele corresponde àquele bin. Para o chunk falso, isso significa que em `alvo + 8` precisa existir um valor com o tamanho certo (as flags são ignoradas). Caso contrário: `malloc(): memory corruption (fast)`.

Isso restringe os alvos: é preciso achar (ou criar) um `size` válido perto do que queremos sobrescrever.

- **Leitura desalinhada**: o alocador não exigia alinhamento na fastbin (até a glibc 2.31). Ponteiros da libc começam com o byte `0x7f`, e lidos com deslocamento viram um `size` de `0x7f`, aceito pelo bin de `0x70`. O alvo clássico era `__malloc_hook - 0x23`, com chunks de `malloc(0x68)`.
- **Escrever o `size` antes**: com outra primitiva, grave um `size` falso ao lado do alvo.

O tcache **não faz essa verificação**, e é por isso que o [Tcache Poisoning](./tcache.mdx#tcache-poisoning) é muito mais simples.

### No tcache

| glibc | Double free no tcache |
|---|---|
| 2.26 a 2.28 | Nenhuma verificação: `free(a); free(a);` funciona direto |
| ≥ 2.29 | [Tcache key](./tcache.mdx#tcache-keys-glibc-229): aborta com `free(): double free detected in tcache 2`. Contorno: sobrescrever a `key` antes do segundo `free`, ou liberar uma vez para o tcache e outra para a fastbin/unsorted bin |
| ≥ 2.32 | O `fd` escrito precisa ser ofuscado ([Safe Linking](./safe-linking.mdx)) |
