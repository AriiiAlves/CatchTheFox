Endianness é a ordem em que os bytes são transmitidos em uma comunicação de dados ou a ordem em que estão inseridos na memória do computador. 

- **Little-endian** - O byte menos significativo vem primeiro (no menor endereço), e o mais significativo vai por último. Se temos `0x0A0B0C0D`, na memória esse número estará como: `0D 0C 0B 0A`. A maioria massiva dos computadores utiliza Little-endian (x86, x86-64 e, na prática, ARM).

- **Big-endian** - A ordem "natural" (a mesma em que escrevemos o número). `0x0A0B0C0D` fica `0A 0B 0C 0D` na memória. Poucos computadores utilizam essa ordem hoje, mas ela é o padrão em protocolos de rede (por isso também é chamada de *network byte order*).

Quando for fazer inserções na memória via inputs no programa (como veremos mais para frente), verifique primeiro o arquivo com `file arquivo` e veja se está em Little-endian ou Big-endian (o `file` mostra `LSB` para Little-endian e `MSB` para Big-endian). Dependendo de como estiver, você terá que mudar a ordem dos bytes inseridos.

## Exemplo

Em um binário x86-64 (little-endian), se o programa compara uma variável com `0xdeadbeef`, os bytes que precisam estar na memória são `ef be ad de`. Você pode conferir no Python:

```py
>>> (0xdeadbeef).to_bytes(4, 'little')
b'\xef\xbe\xad\xde'
>>> (0xdeadbeef).to_bytes(4, 'big')
b'\xde\xad\xbe\xef'
```

O mesmo vale para a leitura: ao olhar a memória no GDB, um valor de 8 bytes como `0x00007ffff7a2d830` aparece byte a byte como `30 d8 a2 f7 ff 7f 00 00`. (No [Pwntools](./pwntools.md), as funções `p32`/`p64` fazem essa conversão para você.)

Note que a ordem invertida vale para **números** (inteiros e endereços). Strings são guardadas na ordem em que são escritas: `"ABCD"` fica `41 42 43 44` na memória.
